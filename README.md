# Proj-C — premium seafood export experience

Cinematic, scroll-driven WebGL site for a global seafood exporter: deep-ocean descent hero, 3D product catalogue (specs, sizes, grading, packaging, HS codes), animated certification seals, a pinned 3D cold-chain journey, an interactive export-route globe with per-region pages, a virtual facility tour and a multi-step B2B RFQ (MOQ, Incoterms, currency-aware pricing, WhatsApp/email).

**Stack:** Vite · Three.js · GSAP + ScrollTrigger · Lenis · self-hosted fonts (Cormorant Garamond, Outfit; Amiri / IBM Plex Sans Arabic loaded only for Arabic).

```bash
npm install
npm run dev        # http://localhost:5173  (?tier=full|lite|static forces a quality tier)
npm run build      # vite build + SEO prerender of /es /ar /zh /ja + sitemap.xml + robots.txt
npm run preview
node scripts/check-i18n.mjs   # verifies all 5 dictionaries have identical keys/placeholders
```

## Before launch — replace the placeholders
| What | Where |
|---|---|
| Site origin (canonical, hreflang, sitemap, OG) | `.env` → `VITE_SITE_URL` |
| Email / WhatsApp number, optional RFQ POST endpoint | `src/config.js`, `.env` → `VITE_RFQ_ENDPOINT` |
| Export hub (arc origin; defaults to Kochi) | `src/config.js` → `HQ` |
| MOQ / container payloads, indicative FX rates | `src/config.js` |
| Products, HS codes, sizes, packs | `src/data/products.js` |
| Regions, ports, transit days, Incoterms | `src/data/regions.js` (then `npm run gen`) |
| Certificates | Seals are illustrative; show only certifications you hold and add certificate IDs |
| JSON-LD contact e-mail / FAQ text | `index.html` |

HS codes, transit times, MOQs and compliance notes are **indicative sample content** and must be confirmed by the business.

## 3D assets
Products are built procedurally (swept geometry + generated skins) so the site works with zero downloads. For photoreal models run `node scripts/optimize-models.mjs` for the Draco/WebP GLB pipeline and list the files in `public/models/manifest.json`; they replace the procedural versions automatically. The facility tour is an illustrative 3D walkthrough — swap in 360° photography when available.

## Quality tiers & performance
* `full` desktop · `lite` mobile/low-core (lower DPR, fewer particles/dots, simpler scenes) · `static` no WebGL, software rasteriser, Save-Data (CSS ocean, SVG product icons, text-based cold chain/tour).
* Three.js and every scene are code-split and lazy-loaded; scenes only render while on screen; one shared RAF.
* Headline text is static HTML, so LCP is independent of WebGL. Measured locally with Lighthouse (mobile, throttled): **static tier 97 perf**, 100 a11y / best-practices / SEO. WebGL tiers need a real GPU to measure — re-test on target devices.

## Media section
Gallery (lightbox), films (privacy-friendly YouTube facade) and downloads live in `src/data/media.js`. Until `src` / `youtubeId` / `file` are filled in, labelled **Sample** placeholders are shown and download buttons open the quote form with the request pre-filled. Filled-in videos and photos are added to the JSON-LD automatically.

## SEO & GEO (generative-engine optimisation)
* Real pages for every language × (home, 4 regions, 7 products) = 60 crawlable URLs, with canonical, reciprocal hreflang, localised titles/descriptions, Open Graph locale alternates and a dated sitemap.
* Localised JSON-LD built at prerender time (`src/seo/jsonld.js`): Organization + OfferCatalog, WebSite, WebPage with `speakable`, BreadcrumbList, FAQPage (6 Q&As, verified against visible text), HowTo (RFQ), ItemList, Product (HS codes/sizes/packs as PropertyValue), Service (regions), VideoObject/ImageObject when media is supplied.
* AI-assistant files: `/llms.txt` (concise map), `/llms-full.txt` (all specs, regions, FAQ, glossary) and a `robots.txt` that explicitly allows search and AI crawlers (GPTBot, ClaudeBot, PerplexityBot, Google-Extended, …). Remove names from `scripts/lib/geo.mjs` if you want to opt out of any.
* Answer-first "Proj-C at a glance" fact block and a 6-question FAQ written as self-contained, quotable statements.
* `npm run build && npm run seo` audits titles, descriptions, h1, canonical, hreflang, JSON-LD validity/FAQ parity, broken links and sitemap coverage.

## i18n & SEO
English, Arabic (RTL), Mandarin, Japanese, Spanish. `data-i18n` attributes drive runtime switching *and* the post-build prerender, so every language has real crawlable HTML at `/xx/` with canonical + hreflang + sitemap alternates. Region pages: `/regions/<slug>/` (generated by `scripts/gen-regions.mjs`).

## Accessibility
Skip link, landmarks, keyboard-operable viewer/globe/tour (arrows, buttons, region chips, stage buttons), ARIA tabs/radiogroup/live regions, validated multi-step form with announced errors, `prefers-reduced-motion` + manual pause toggle, sound off by default with mute toggle (Web Audio, procedural — no audio files).
